# 5. ACL — Interview Answers

## 🔴 Very Important

### 1. What is an ACL?

ACL stands for Access Control List. It is a set of rules used to permit or deny network traffic based on defined criteria.

### 2. Why is ACL used?

ACLs are used to control network traffic, restrict unauthorized access and improve network security.

### 3. How does ACL control traffic?

An ACL checks traffic against its rules. Depending on the matching rule, the traffic is permitted or denied.

### 4. What is a standard ACL?

A standard ACL primarily filters traffic based on the source IP address.

### 5. What is an extended ACL?

An extended ACL can filter traffic using more detailed criteria such as source and destination IP addresses, protocols and port numbers.

### 6. Standard vs Extended ACL

| Standard ACL | Extended ACL |
|---|---|
| Mainly source IP | Source + destination IP |
| Less specific | More specific |
| Basic filtering | Can filter protocol/ports |
| Simpler | More granular |

**Interview answer:**

Standard ACLs provide basic filtering mainly based on source IP, while extended ACLs provide more granular filtering based on source, destination, protocol and ports.

### 7. What is inbound ACL?

An inbound ACL checks traffic as it enters an interface.

### 8. What is outbound ACL?

An outbound ACL checks traffic as it leaves an interface.

### 9. What is implicit deny?

Implicit deny means that traffic that doesn't match an explicit permit rule is denied by default at the end of the ACL.

**Important:**

No matching permit → traffic denied

### 10. What happens if no ACL rule matches?

If no rule matches, the implicit deny at the end of the ACL causes the traffic to be denied.

### 11. ACL vs Firewall

An ACL is generally a set of traffic-filtering rules configured on network devices, while a firewall is a broader security system that can provide traffic filtering, stateful inspection and other security capabilities.

## 🟠 Important

### 12. Can ACL filter by IP address?

Yes. ACLs can filter traffic based on source and, depending on the ACL type, destination IP addresses.

### 13. Can ACL filter by port?

Yes. Extended ACLs can filter traffic based on TCP or UDP port numbers.

### 14. Can ACL filter by protocol?

Yes. Extended ACLs can specify protocols such as TCP, UDP or ICMP.

### 15. Where should ACLs be placed?

For an interview:

ACL placement depends on the purpose of the rule. In general, standard ACLs are often placed closer to the destination, while extended ACLs are often placed closer to the source so unwanted traffic can be stopped earlier.

That's a good interview-level answer.

### 16. What is permit?

Permit means the traffic matching that ACL rule is allowed.

### 17. What is deny?

Deny means the traffic matching that ACL rule is blocked.

### 18. What is ACL rule order?

ACL rules are evaluated in sequence, normally from top to bottom.

### 19. Why does rule order matter?

Because:

The first matching rule determines the result.

**Example:**

Rule 1 → Permit  
Rule 2 → Deny

If traffic matches Rule 1, it is permitted and the later rule is not evaluated for that traffic.

**Interview line:**

Therefore, a more specific rule may need to be placed before a broader rule.

## 🟡 Lower Priority

### 20. Numbered vs Named ACL

A numbered ACL is identified by a number, while a named ACL is identified by a descriptive name and is generally easier to manage and modify.

### 21. ACL wildcard masks

A wildcard mask is used in some network-device ACL configurations to specify which bits of an IP address should be matched and which can vary.

For basic understanding:

0 → must match  
1 → can vary

### 22. Reflexive ACL

A reflexive ACL can dynamically create temporary filtering entries based on outbound traffic, helping permit corresponding return traffic.

### 23. Time-based ACL

A time-based ACL applies access rules only during specified times.

**Example:**

Allow access during working hours but deny it outside those hours.

## 🧠 ACL 20-SECOND REVISION

ACL = rules that permit or deny traffic. Standard ACL mainly checks source IP. Extended ACL can check source/destination IP, protocol and ports. ACL rules are processed in order, and unmatched traffic is normally denied by the implicit deny.
