# 2. HTTP / HTTPS FUNDAMENTALS

## 🔴 Very Important

### 1. What is HTTP?
HTTP = **Hypertext Transfer Protocol**.  
Application-layer protocol for communication between clients and web servers.

### 2. How does HTTP work?
Client sends **HTTP request** → Server processes → Server sends **HTTP response** (status code + headers + body).

### 3. What is an HTTP request?
Message from client asking server for resource/operation.

### 4. What is an HTTP response?
Message from server containing result of request.

### 5. HTTP request methods
- GET → Retrieve data  
- POST → Submit/create data  
- PUT → Replace/update resource  
- PATCH → Partially update resource  
- DELETE → Remove resource  
- HEAD → Request headers only  
- OPTIONS → Request communication options  

### 6. GET vs POST
- GET → Retrieves data, parameters in URL, cacheable.  
- POST → Submits data, parameters in body, modifies server state.

**Interview answer:**  
GET retrieves information, POST submits or creates resources.

### 7. PUT vs PATCH
- PUT → Replace entire resource.  
- PATCH → Modify part of a resource.

### 8. HTTP status codes
- 2xx → Success  
- 3xx → Redirection  
- 4xx → Client error  
- 5xx → Server error  

Examples:  
200 OK, 201 Created, 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 500 Internal Server Error.

### 9. HTTP header
Metadata in request/response (e.g., Content-Type, Authorization).

### 10. HTTP body
Contains actual data being sent.

### 11. URL
Uniform Resource Locator → identifies resource location.  
Example: `https://example.com/products`

### 12. What is HTTPS?
HTTPS = **Hypertext Transfer Protocol Secure**.  
HTTP protected using **TLS**.

### 13. HTTP vs HTTPS
| HTTP | HTTPS |
|------|-------|
| Not encrypted | Encrypted with TLS |
| Port 80 | Port 443 |
| Vulnerable | Secure |

### 14. Why is HTTPS secure?
Provides **encryption, authentication, integrity protection** via TLS.

### 15. TLS
**Transport Layer Security** → cryptographic protocol for secure communication.

### 16. SSL/TLS certificate
Authenticates server identity + enables secure TLS connection.

### 17. Opening an HTTPS site
1. DNS resolves domain → IP  
2. TCP connection established  
3. TLS handshake → secure channel  
4. HTTP request sent  
5. Server responds → browser displays page  

**Interview answer:**  
DNS → TCP → TLS → HTTP request/response → webpage displayed.

### 18. Encryption
Transforms readable data into unreadable form without key.

### 19. Authentication
Verifies identity of user/device/server.

### 20. Data integrity
Ensures data not modified/corrupted.

### 21. HTTP statelessness
Each request independent; protocol does not remember previous requests.

### 22. Cookie
Small piece of data stored on client browser.

### 23. Session
Period of interaction between client and server, maintaining state.

### 24. Cookie vs Session
- Cookie → Client-side storage  
- Session → Server-side state

### 25. HTTP keep-alive
Allows reuse of a single connection for multiple requests/responses.

---

## 🟠 Important

### 26. HTTP/1.0
Early version, connections closed after each request.

### 27. HTTP/1.1
Introduced persistent connections + improvements.

### 28. HTTP/2
Binary framing, multiplexing, header compression → faster.

### 29. HTTP/3
Uses **QUIC over UDP** instead of TCP.

### 30. HTTP/1.1 vs HTTP/2
- HTTP/1.1 → Text-based, limited.  
- HTTP/2 → Binary framing, multiplexing, efficient.

### 31. Persistent connection
Connection remains open for multiple requests/responses.

### 32. Content-Type
Header specifying format of body.  
Example: `Content-Type: application/json`

### 33. Accept header
Specifies media types client can accept.  
Example: `Accept: application/json`

### 34. Authorization header
Carries credentials for authentication.  
Example: `Authorization: Bearer <token>`

### 35. Host header
Specifies hostname of server requested.

### 36. Cache-Control
Header defining caching rules.

### 37. HTTP caching
Storing/reusing resources to reduce traffic + improve speed.

### 38. Proxy
Intermediary forwarding client requests to server.

### 39. Reverse proxy
Receives client requests → forwards to backend servers.

### 40. Proxy vs Reverse Proxy
- Proxy → Represents client  
- Reverse Proxy → Represents server

### 41. Redirect
Tells client resource is at another location.  
Examples: 301 Permanent, 302 Temporary, 304 Not Modified.

### 42. Other status codes
- 405 → Method Not Allowed  
- 429 → Too Many Requests  
- 502 → Bad Gateway  
- 503 → Service Unavailable

## 🟡 Lower Priority

### 43. HTTP pipelining
Multiple requests sent without waiting for responses (rarely used).

### 44. HTTP/2 multiplexing
Multiple streams share one connection simultaneously.

### 45. HPACK
Header compression format used in HTTP/2.

### 46. QUIC
Transport protocol over UDP → reliable, encrypted, multiplexed.

### 47. Why HTTP/3 uses QUIC
Avoids TCP limitations, improves speed + security.

### 48. HSTS
HTTP Strict Transport Security → forces browsers to use HTTPS.

### 49. CSP
Content Security Policy → controls which resources a webpage can load.

### 50. CORS
Cross-Origin Resource Sharing → controls requests across different origins.

### 51. OPTIONS request
Method to query communication options supported.

### 52. HEAD request
Similar to GET but returns headers only.

### 53. Chunked transfer encoding
Allows sending response in chunks when size unknown.

### 54. HTTP trailers
Headers sent after message body (e.g., in chunked responses).

### 55. TLS cipher-suite negotiation
Client/server agree on cryptographic algorithms + keys during handshake.

### 56. What does 405 Method Not Allowed mean?
405 Method Not Allowed → The HTTP method used is not supported for the requested resource.  
Example: Sending DELETE to an endpoint that only supports GET.

### 57. What does 429 Too Many Requests mean?
429 Too Many Requests → The client has sent too many requests in a given period and may be rate-limited.

### 58. What does 502 Bad Gateway mean?
502 Bad Gateway → A gateway or proxy received an invalid response from an upstream server.

### 59. What does 503 Service Unavailable mean?
503 Service Unavailable → The server is temporarily unable to handle the request (overload or maintenance).

### 60. What is HTTP pipelining?
HTTP pipelining → Allows multiple HTTP requests to be sent without waiting for each previous response.  
*Rarely used in modern browsers.*

### 61. What is HTTP/2 multiplexing?
HTTP/2 multiplexing → Multiple independent request/response streams share a single connection simultaneously.

### 62. What is HPACK?
HPACK → Header compression format used by HTTP/2 to reduce header size.

### 63. What is HTTP/3?
HTTP/3 → Modern HTTP protocol using **QUIC** as transport instead of TCP.

### 64. What is QUIC?
QUIC → Transport protocol built over UDP. Provides reliable delivery, encryption, and multiple streams.

### 65. Why does HTTP/3 use QUIC?
HTTP/3 uses QUIC to provide efficient, secure, multiplexed communication while avoiding TCP limitations.

### 66. What is HSTS?
HSTS = **HTTP Strict Transport Security**.  
Tells browsers to always use HTTPS instead of HTTP.

### 67. What is CSP?
CSP = **Content Security Policy**.  
Controls which resources a webpage can load or execute.

### 68. What is CORS?
CORS = **Cross-Origin Resource Sharing**.  
Controls whether a web page can make requests to a different origin.

### 69. What is an HTTP OPTIONS request?
OPTIONS → Method used to request information about communication options supported by a server/resource.

### 70. What is an HTTP HEAD request?
HEAD → Similar to GET but only returns headers, not the body.

### 71. What is chunked transfer encoding?
Chunked transfer encoding → Allows HTTP/1.1 responses to be sent in chunks when total size is unknown.

### 72. What is an HTTP trailer?
HTTP trailers → Additional headers sent after the message body (e.g., in chunked responses).

### 73. Detailed TLS cipher-suite negotiation
During TLS handshake, client and server negotiate compatible cryptographic algorithms and establish keys for secure communication.  
*For fresher interviews, knowing the basics is enough — don’t dive too deep into internals.*

# 🧠 HTTP/HTTPS 30-Second Revision

**Memorize this:**  
HTTP = communication protocol between client/server.  
HTTPS = HTTP + TLS → secure, encrypted, authenticated.  
Methods: GET, POST, PUT, PATCH, DELETE.  
Status codes: 2xx success, 3xx redirect, 4xx client error, 5xx server error.  
Headers = metadata, body = data.  
Cookies (client-side) vs Sessions (server-side).  
HTTP/2 → multiplexing, HTTP/3 → QUIC.  
Security: TLS, HSTS, CSP, CORS.

**Remember:**  
- GET → Retrieve  
- POST → Submit  
- PUT → Replace  
- PATCH → Modify  
- DELETE → Remove  
- 200 OK → Success  
- 404 → Not Found  
- 500 → Server Error  
- HTTPS → Secure with TLS  
- Cookie → Client-side  
- Session → Server-side  
- Proxy → Client-side intermediary  
- Reverse Proxy → Server-side intermediary  

**Interview answer:**  
> HTTP is a stateless protocol for client-server communication. HTTPS adds TLS for encryption, authentication, and integrity. Common methods include GET, POST, PUT, PATCH, DELETE. Status codes indicate request results, and headers provide metadata. Modern versions like HTTP/2 and HTTP/3 improve performance and security.
