# 13. UDP FUNDAMENTALS

## 🔴 Very Important

### 1. What is UDP?
UDP = **User Datagram Protocol**.  
Connectionless transport-layer protocol providing low-overhead communication without guaranteeing delivery or ordering.

### 2. What does UDP stand for?
UDP → User Datagram Protocol.

### 3. Is UDP connection-oriented or connectionless?
UDP is **connectionless**.

### 4. UDP vs TCP
| UDP | TCP |
|-----|-----|
| Connectionless | Connection-oriented |
| No guaranteed delivery | Reliable delivery |
| No guaranteed ordering | Ordered delivery |
| Lower overhead | Higher overhead |
| No retransmission | Retransmission |
| No flow control | Flow control |
| No congestion control | Congestion control |

### 5. Is UDP reliable?
No. UDP does not provide reliability. Applications must implement their own mechanisms if needed.

### 6. Does UDP guarantee packet delivery?
No. Datagram may be lost.

### 7. Does UDP guarantee packet ordering?
No. Datagrams may arrive out of order.

### 8. Why is UDP faster than TCP?
Lower overhead → no connection setup, acknowledgements, retransmissions, ordering, flow/congestion control.

### 9. When should UDP be used?
When low latency and low overhead are more important than guaranteed delivery/ordering.

### 10. Applications using UDP
- DNS  
- DHCP  
- Real-time voice/video  
- Online gaming  
- Streaming  

### 11. What is a UDP datagram?
Unit of data transmitted by UDP → header + application data.

### 12. Does UDP use ports?
Yes. Source + destination ports identify applications/services.

### 13. What is UDP checksum?
Detects errors/corruption in datagram.

### 14. What happens if a UDP packet is lost?
UDP does not retransmit. Application must handle recovery if needed.

### 15. Why choose UDP over TCP?
For low latency, low overhead, real-time communication (voice, video, gaming).

### 16. Does UDP perform retransmission?
No.

### 17. Does UDP perform flow control?
No.

### 18. Does UDP perform congestion control?
No. Applications may implement their own.

**Interview answer:**  
“I would use UDP when low latency and low overhead are more important than guaranteed delivery and ordering. For example, real-time voice/video or online gaming.”

## 🟠 Important

### 19. What is a UDP datagram?
Basic unit of data → header + payload.

### 20. What is the UDP header?
Header identifying source/destination ports, length, checksum.

### 21. Fields in UDP header
- Source Port  
- Destination Port  
- Length  
- Checksum  

### 22. UDP source port
Identifies sending application/service.

### 23. UDP destination port
Identifies receiving application/service.

### 24. UDP length
Specifies total length of datagram (header + data).

### 25. UDP checksum
Detects errors in header + data.

### 26. Why does UDP have less overhead?
Small header, no connection setup, no retransmission, no ordering, no flow/congestion control.

### 27. Can UDP broadcast?
Yes, with IPv4 broadcast.

### 28. Can UDP multicast?
Yes, supports multicast communication.

### 29. What is UDP fragmentation?
UDP does not fragment. IP layer may fragment packets if larger than MTU.

### 30. DNS and UDP
DNS commonly uses UDP for queries/responses (low overhead, fast).

### 31. Can DNS use TCP?
Yes, for large responses or zone transfers.

### 32. Why can DNS use UDP?
Most queries/responses are small, no need for connection-oriented transport.

### 33. What happens if a UDP datagram is lost?
It is simply lost unless application implements recovery.

## 🟡 Lower Priority

### 34. UDP checksum calculation
Detects errors using one’s-complement arithmetic + pseudo-header.  
*Interview: know purpose, not calculation details.*

### 35. UDP fragmentation details
Datagrams carried in IP packets. IPv4 may fragment; IPv6 does not fragment in transit.

### 36. UDP-Lite
Variant of UDP allowing partial checksum coverage (useful for apps tolerating minor corruption).

### 37. Multicast behavior
Sender transmits to group of receivers. UDP commonly used for multicast.

### 38. UDP tunneling
Encapsulating other protocols/traffic inside UDP packets.

### 39. QUIC vs traditional UDP
QUIC uses UDP but adds reliability, congestion control, encryption, multiplexing. Traditional UDP apps don’t have these features.

### 40. Application-level reliability over UDP
Applications can implement reliability (sequence numbers, ACKs, retransmissions, ordering).

# 🧠 UDP 30-Second Revision

**Memorize this:**  
UDP = connectionless, low-overhead, no guarantee of delivery/ordering.  
Used for DNS, DHCP, streaming, gaming, real-time communication.  
Header fields: Source Port, Destination Port, Length, Checksum.  
Supports broadcast + multicast.  
No retransmission, flow control, congestion control.  
Applications can add reliability if needed.

**Remember:**  
- UDP → Fast, connectionless  
- TCP → Reliable, connection-oriented  
- Broadcast + Multicast supported  
- DNS → UDP for queries, TCP for large responses  
- UDP-Lite → Partial checksum  
- QUIC → UDP + reliability + encryption  

**Interview answer:**  
> UDP is a connectionless transport-layer protocol offering low latency and low overhead. It does not guarantee delivery or ordering, making it suitable for real-time applications like voice, video, gaming, and DNS queries. Reliability can be added at the application level if required.
